## 1. What the app is (as built)

It's a single-screen mobile web app. At the top is a breathing **orb**: an iframe running `isos.html`, scaled by GSAP on a 4-2-6 cycle, with 100 rotating pt-BR phrases above it. At the bottom are **6 option tiles**. Tapping a tile opens a **bottom sheet** that walks a JSON-driven **flow** one beat at a time (`_meta.principle: "one_action_per_beat"`).

```
index.html
 ├─ preloader.js (sync, head) ── holds the entire UI behind a scripted text sequence
 ├─ remixicon (jsdelivr) · core.js (cdn.apollo.rio.br → loads ~25 more files) · gsap (cdnjs) · Google Fonts ×2
 ├─ style.css
 ├─ <iframe src=isos.html>  (orb visuals, pause/play via postMessage)
 ├─ <audio clocks.flac>     (ambient, fades 0→85% over 12 s)
 ├─ data.embed.js  → window.SOS_DATA   (PRODUCTION CONTENT SOURCE)
 └─ script.js      → engine: boot, orb, audio, zen, sheet, node renderer, risk model, persistence
```

### Boot sequence (measured live)
1. The preloader forces a **white** page, then fades it to black.
2. It shows 5 reassurance lines with pauses in between (≈35 s of hold time plus fades).
3. **The app became usable at 52.8 s** in the test run with no taps. One tap skips the preloader, but nothing on screen says so.
4. `script.js` only starts `boot()` after the `preloader:revealed` event (90 s safety net). Until then the static tiles in the HTML have **no click handlers**.
5. A welcome toast appears: "Estamos contigo aqui.. Sem pressa, tá?"
6. The first tap anywhere starts the ambient audio. Opening any flow also starts it.

### Engine model (`script.js`)
| Concept | How it works |
|---|---|
| Node types | `choice` (question + buttons), `info` (text + "continuar devagar"), `task` (checklist; continue shows once all are ticked), `action` (tel/sms/WhatsApp/CAPS list), `redirect` (switch flow or "ficar aqui") |
| Task variants | `default`, `breath_guide` (patterns 4-6 / 4-2-6 / box-4, 10 cycles), `crt_pause` (10 s countdown), `contact_pick` (Contact Picker API → SMS, else WhatsApp), `call`, `sms`, `media` (inline video) |
| Fast-lane | A "preciso de algo agora" button, shown only on node `a1` of torto/panico/realidade/trava/falar |
| Crisis bar | A sticky CVV 188 + SAMU 192 bar. It shows in `panico`, `falar`, `cssrs`, on nodes with `crisis:true`, or when the session risk is MODERATE or higher. **It does not show in `torto` by default.** |
| Risk model | IDLE→LOW→MODERATE→HIGH→EMERGENT. It is set by `choice.riskLevel` and `node.riskOnEnter`, **only ever goes up**, and is saved to sessionStorage and localStorage. At EMERGENT, `locked` only shows a toast; the sheet still closes. |
| Persistence | `localStorage.sos_flow_progress` = {flow, node, tasks done, risk}. Reopening the same flow **resumes silently** at the saved node. |
| Progress bar | Based on the node's position in the JSON **key order**, not on the path the user took, so it can jump backwards or forwards. |
| Unused data | `choice.delta` (on every choice) is never read. `BREATHE_PHRASES` pools are classified by regex. `nextBreathePhraseRaw` and `showBreathePhrase` are dead code. `loadData()` fetches (`../data.json`, `./data.json`) never run because `SOS_DATA` is already present. |

## 3. Critical findings (safety, trust, privacy)

These rank above design polish. Most are small fixes, but they have to be *decided* before 001–003 (see §7).

| # | Finding | Evidence | Why it matters |
|---|---|---|---|
| **C1** | **The preloader blocks help for about 52 s and opens with a white flash** | Measured live. `preloader.js:21-44,227-238`. `script.js:1715-1730` | A person in panic gets over half a minute of text before any tile works. The white flash contradicts the dark, low-light principle. |
| **C2** | **The privacy promise doesn't match the code.** The preloader says *"Espaço protegido e anônimo · Não guardamos suas informações aqui"* | `localStorage.sos_flow_progress` stores the flow, node and **risk level (up to EMERGENT, which comes from suicide-screening answers)** with no expiry. `core.js` loads ~25 files, including a **tracking call `/wp-json/apollo/v1/track/batch`**, jQuery, a translate library and popper. CDN font and icon hosts also see the user's IP. | Under LGPD, health data is sensitive data (Art. 11). On a shared phone, a partner or parent could read a suicide-risk flag. If the promise turns out to be false, trust in the whole harm-reduction project suffers. |
| **C3** | **Debug telemetry ships to production** | `script.js:131,315` POSTs to `http://127.0.0.1:7796/ingest/...` on every audio event and **every 2 s** via the GSAP ticker. The live run showed repeated `ERR_CONNECTION_REFUSED`. | Battery drain and console noise. It can also trigger the browser's *local network access* prompt, which is exactly the kind of interruption the app is meant to avoid. |
| **C4** | **The CAPS directory is unverified and looks partly placeholder** | `resources.caps_rio`: 7 "CAPS III" entries whose street names match the unit names ("R. Dona Ivone Lara, 50", "R. Paulo Portela, 300") and whose phone numbers follow patterns (`3355-9000`/`3355-9100`). `caps_intro` calls CAPS *"hospital psiquiátrico público"* | A wrong phone number or address during a crisis causes real harm. A CAPS is a community care service, not a hospital. The doctors and psychologists need to validate every entry before users see it. |
| **C5** | **Legal claim that needs checking** | `samu.instant_rescue`: *"não acionam a polícia por uso de drogas em socorros médicos"* | If this doesn't hold in every situation, it breaks trust at the worst possible moment. It needs a legal and SAMU-protocol review, and maybe softer wording. |
| **C6** | **The substance flow has the weakest emergency access** | `torto` is not in `CRISIS_FLOWS`. The first `tel:` is 8 steps in. The copy reassures (*"o corpo está processando, não colapsando"*) with no red-flag check (chest pain, overheating, seizure, fainting, slow breathing). | This is the flow most likely to involve a real medical emergency (stimulants, MDMA overheating, depressant mixes). |
| **C7** | **Emergency numbers depend on JavaScript, GSAP and the preloader** | Static HTML has no `tel:` link. `showOverlay()` calls `gsap` with no guard (`script.js:970-976`). | If a CDN fails (bad signal at carnival), the sheet that holds 188 and 192 never opens. |
| **C8** | **Audio starts without being asked** | `startFlow()` calls `startAmbientAudio(true)` (`script.js:1013`). The first tap anywhere also starts it. When playback fails, a toast says *"não consegui tocar o som. tenta de novo."* | Sound in a public place or a bathroom can expose the person. An error toast in the middle of a crisis adds stress. |
| **C9** | **Silent resume** | `startFlow` restores the saved node with no prompt. | Opening "Pânico" days later can drop the person straight into a SAMU or high-risk screen from a past episode. |

## 4. Design map (summary; full audit in `000-auditoria-design.md`)

**What's already good:** the base is near-black (`#060508`, not pure black). The sheet uses `dvh` and respects the notch and home indicator. Most touch targets are at least 48 px. The body text has about 11.5:1 contrast. `aria-live` is used on the breathing label and the toast. Esc closes the sheet. The motion is slow and cushioned (the easing is a smootherstep curve).

**Why it feels like a web page rather than a premium app:**
1. No manifest, service worker or offline mode, even though the "app-capable" meta tags are set.
2. Twelve or more third-party hosts, **GSAP loaded twice** (cdnjs plus core.js), Google Fonts loaded twice, and jQuery and Lenis pulled in by core.js on a page that doesn't scroll.
3. There's no token system for motion, spacing or z-index (14+ hard-coded durations), and the icon tints are inline `rgba()` values instead of the existing `--tint-*` tokens.
4. `prefers-reduced-motion` only freezes the orb's scale. The aurora, motes, the blob loop in `isos.html` and the breathing timeline keep running.
5. The orb uses pure `#f0f`/`#0ff` neon with large-radius blur. That's the most photosensitive-unfriendly pair of colors, and the population here may be on psychedelics.
6. `user-scalable=no`, no `:focus-visible` anywhere, no focus trap or focus return in the dialog, and `--text-faint` fails AA contrast at the 10.5–12 px sizes it's used for. The "toque em qualquer lugar para começar" hint is about 0.6:1, so effectively invisible.
7. There is no Wake Lock, so the screen can dim in the middle of a 2-minute breathing exercise.
8. There's no landscape layout and no desktop layout: the sheet stretches full width.
9. The home tile grid uses `wrap-reverse` with `flex-end`. At 375 px that gives 4 tiles on the bottom row and 2 right-aligned tiles above, an uneven pyramid. Emergency ("Resgate") sits top-right, the hardest spot to reach with one hand.
10. The sheet is translucent. While it slides in, the orb and the breathing phrases show through the flow text, so two voices talk at once.

## 5. Content map (summary; full audit in `000-auditoria-conteudo.md`)

**Global category balance (191 nodes; one primary category per node, classified by Sonnet):**

| Category | Nodes | % |
|---|---|---|
| Motivational ("vai passar", validation) | 30 | 15.7 |
| Emergency (SAMU/CVV/CAPS/first aid) | 24 | 12.6 |
| Triage (routing question) | 18 | 9.4 |
| Welcome (acolhimento) | 14 | 7.3 |
| Therapeutic (CBT reframe, behavioural activation, journaling, CRT pause…) | 14 | 7.3 |
| Physiological (cold water, posture, hydration) | 13 | 6.8 |
| Breathing / Grounding / Social connection / Redirect | 12 each | 6.3 each |
| Psychoeducation | 11 | 5.8 |
| Environment (volume, light, quiet corner, distance from the substance) | 9 | 4.7 |
| Suicide risk (C-SSRS) | 7 | 3.7 |
| **Harm reduction (substance-specific safety)** | **3** | **1.6** |

Grouped: **techniques (physiological + breathing + grounding + environment) 24.1%**, motivational 15.7%, therapeutic 7.3%, psychoeducation 5.8%.

**Key takeaways for phase 002:**
1. **Harm reduction is almost missing from a harm-reduction app.** There are only 3 nodes, all in `torto`. Missing entirely: naloxone, GHB/"G", MDMA or stimulant overheating, mixing combinations beyond depressants, and urge surfing or delay-and-distract for cravings and relapse.
2. **Motivational beats are the biggest single category** and bunch up at the ends of flows (`torto` has 4 of its last 6 beats motivational; `trava.m11` and `m14` are **word-for-word duplicates**).
3. **Technique repetition:** cold water or the dive reflex appears in **12 nodes**, and the same 4-6-10 breathing paragraph is copied into **9 nodes**. That's a maintenance risk and makes flows feel repetitive when the user is redirected between them. It needs a shared component.
4. **Uneven pacing:** `panico` runs 9 regulation techniques in a row before any grounding. `realidade` has no breathing on the "a bit better" main path. In `torto` and `falar`, breathing first shows up at beat #10.
5. **Evidence-based techniques not present:** a full DBT TIPP set, full PMR, butterfly hug, safe-place imagery, a HALT check, a full Stanley-Brown safety plan (only means restriction exists), and trigger mapping that actually reflects on the trigger. "Set and setting" appears in tasks but is never taught as an idea to carry into the future. That last one is the "reflection on environment" you asked for.
6. **Unconditional reassurance with no red-flag check** ("você não está em perigo real", "seu corpo não está morrendo"). This is the top clinical gap. It connects to C6.
7. **Needs clinical review:**
   - "1 copo (250 mL) por dose"
   - "baixa o coração de verdade" with no caveat (arrhythmia, vasovagal)
   - C-SSRS `c6` asks about "se machucar" instead of the spec's "pôr fim à vida" (a fidelity gap)
   - `c5` = Sim skips `c6` (differs from `workflows 002.md`; confirm it was intended)
8. **Tone:** 15 weakest and 10 best lines are in the full audit. The weak ones are mostly absolutes, DSM labels ("despersonalização/desrealização" at `realidade.a2`), stacked imperatives (`realidade.m12`), gendered "Obrigado", and the confusing "Eles não se importam" at `samu.a2_unsure`.
9. **Label drift:** redirect copy says "Travei", "Onde estou?" and "Tô sozinho", but the home tiles say "Paranoia", "Onde eu tô?" and "Solidão". The HTML sub-label "Medo constante" also differs from the JS "Muito medo". tu/você is consistent. The ".." ellipsis style is used everywhere; decide whether that's the house voice.

> Note from Opus verification: the content agent said CAPS is never called a hospital. That's true inside the flow nodes, but `resources.caps_intro` (shown above the CAPS list) does say "hospital psiquiátrico público", so C4 stands. The `falar.wa_from_yes` "PLACEHOLDER" href is replaced at render time by `buildWhatsAppHref`, so it's safe as long as the template key exists.

## 6. Recommended skeleton (file and folder structure)

Principle: **content is the product.** Clinicians edit content, engineers edit the engine, and a build step joins the two. There is one source of truth, checked on every change.

```
sos/app/
├─ index.html                     # shell only; static tel:192 / tel:188 fallback in markup
├─ manifest.webmanifest           # (003) installable, standalone, dark theme_color
├─ sw.js                          # (003) offline: shell + content + fonts + icons cached
├─ assets/
│  ├─ css/  tokens.css · base.css · components/*.css · motion.css (reduced-motion gate)
│  ├─ js/   engine/{flow-engine.js, risk.js, storage.js, progress.js}
│  │        ui/{orb.js, sheet.js, toast.js, audio.js, preloader.js, a11y.js}
│  ├─ vendor/ gsap.min.js · remixicon subset (self-hosted, offline-safe)
│  ├─ fonts/ (self-hosted woff2, only the used weights)
│  ├─ media/ clocks.* · voice videos · thumb.png
│  └─ orb/  isos.html
├─ content/                       # ← edited by the clinical team, reviewed via PR
│  ├─ flows/ torto.json · panico.json · realidade.json · trava.json · falar.json · samu.json · cssrs.json
│  ├─ resources/ hotlines.json · caps-rio.json (with source + verified_at + verified_by) · whatsapp.json
│  ├─ copy/ ui-strings.pt-BR.json · breathe-phrases.json · preloader.json
│  └─ schema/ flow.schema.json    # node types, required fields, allowed variants
├─ build/  data.embed.js          # GENERATED; never hand-edited
├─ tools/  build-content.js · validate-flows.js (orphans, dead ends, schema) · mermaid.js · content-lint.js
├─ docs/   workflows-001.md · workflows-002.md · tone-guide.md · clinical-review-log.md
├─ _audit/ 000-mapeamento/ · 001-design/ · 002-conteudo/ · 003-melhorias/
└─ _archive/ index.v0.html · json/data.json · isos2.html · iframe-to-ij-protected.html
```

Also recommended: `git init` (the project isn't under version control yet). Every clinical edit to content then becomes a diff that can be reviewed and signed off, which is the audit trail you asked for.
